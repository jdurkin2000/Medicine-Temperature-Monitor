# Development guide

## Supported environment

- Windows 11
- Code Composer Studio 21.0.0 at `C:/ti/ccs2100`
- TI MSP430 Code Generation Tools 21.6.2 LTS
- MSP430Ware 3.80.14.01-derived project
- MSP-EXP430FR6989 LaunchPad with onboard eZ-FET

CCS is the authoritative compiler, linker, project configuration, and flash
tool. Editor diagnostics are useful but do not replace a TI compiler build.

## VS Code workflow

Open the repository root, not `Smart Monitor`. Install the recommended
Microsoft C/C++ extension when prompted.

- Build: `Ctrl+Shift+B`, then `CCS: Build Smart Monitor (Debug)`.
- Clean: **Tasks: Run Task**, then `CCS: Clean Smart Monitor (Debug)`.
- Build and program: **Tasks: Run Task**, then
  `CCS: Build and Flash Smart Monitor (Debug)`.

The flash task expects `Smart Monitor/Debug/Smart Monitor.out` and the onboard
eZ-FET described by `Smart Monitor/targetConfigs/MSP430FR6989.ccxml`.

The checked-in VS Code settings provide target headers and defines for
IntelliSense. `Smart Monitor/.clangd` is generated by CCS and suppresses clangd
diagnostics; this repository intentionally uses the Microsoft C/C++ extension
instead of a clangd extension.

## Code Composer Studio workflow

Import `Smart Monitor` as an existing CCS managed-build project, select the
`Debug` configuration, and build before starting a debug session. The target
is `MSP430FR6989` using the `TI MSP430 USB1` connection.

If source changes while a debug session is open, rebuild and load the newly
generated image before restarting. Restarting alone runs the previously loaded
image.

Do not manually edit `.project`, `.cproject`, `.ccsproject`, or `.settings` to
change CCS configuration. Use CCS project tooling so its metadata remains
consistent.

## UART monitor

Connect to the Windows port named `MSP Application UART1` (COM10 on the
original development machine) with:

- 9600 baud;
- 8 data bits;
- no parity;
- 1 stop bit; and
- no flow control.

The firmware transmits Fahrenheit with two printed decimal places and `F`,
regardless of the LCD unit. It does not send CR or LF, so readings appear
concatenated. The sensor path has less effective precision than the printed
second decimal digit; do not treat that digit as additional accuracy.

All thresholds and stored readings use signed tenths of a degree Celsius.

## Generated and managed files

`Smart Monitor/main.pp` and everything under `Smart Monitor/Debug/` are build
products, not source. The files under `Smart Monitor/driverlib/` are vendored
TI code and should not carry application behavior.

## Verification expectations

After a firmware edit:

1. build the CCS `Debug` configuration;
2. report the exact build result, including warnings;
3. identify hardware behavior that was not exercised locally; and
4. provide a short bench test for that behavior.

Power-related changes should also follow the measurement method in
[Power budget](power-budget.md). Timing, pin, or timer changes should be checked
against [Architecture and design](architecture-and-design.md) and
[Hardware](hardware.md).
